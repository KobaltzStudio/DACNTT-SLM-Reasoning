# Phase 1 — Controller and hook acceptance

PASS on Windows CPU. Four live-artifact dry-run plans were built with a runner that fails on any subprocess: A S1 = 0 actions, B S1 = 0, A S2 = 4 (D_dev continuation, checkpoint log, hook, capability state), and B S2–S3 = 16 (fresh NLL at S1/S2 and parent adapter chaining). A S2 does not plan training or S3. The controller emits only `--split dev` for model evaluation. Saved hook help exposes all required input arguments, with dynamic checkpoint identity and one-based integrated rounds; P2 baseline selection subtracts one. P1-DEFICIT is deficit-only. P1P2 ranks 0.5 deficit + 0.5 percentile L_proxy. Shared S0, frozen LoRA and strict scoring remain in place.

D_test input audit verified 1,319 unique source/split IDs with zero overlap with D_dev or D_pool. Frozen hashes for the source split, ID list and GSM8K input match the exact LF canonical bytes after CRLF normalization. The release and package retain and pin the original Windows bytes. The legacy evaluator uses greedy decoding and `eval_metrics` strict `status == valid`. Its public test CLI now stops and directs the operator to the guarded entry point; the old historical runner that requests per-round D_test is outside this handoff. Existing D_dev commands are unchanged.

Five synthetic CPU gate tests passed. The guard requires a complete FINAL G7 on all candidates, an externally recorded G7 SHA, matching re-derived dev selection, checkpoint SHA and evaluator fingerprint. It checks output collision before the evaluator, then validates coverage and reports Wilson 95% intervals. Only integrated methods are enabled by the wrapper. Current real G7 remains PARTIAL, so D_TEST_READINESS=PARTIAL and D_TEST_EXECUTION=NOT_RUN.
