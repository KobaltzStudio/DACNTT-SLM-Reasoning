# Rollback plan

1. Original repository was not migrated, renamed or cleaned destructively. Roll back deployment by stopping use of the package and continuing from the original manual root on the same branch. Preserve any active process, lock, package and log until ownership and outputs are verified.
2. If any transfer SHA or Linux runtime locator fails, leave the destination isolated. Compare trusted manifest, paths, platform line endings and source; use a fresh versioned destination for corrected transfer. Do not overwrite original research evidence or silently correct recorded hashes.
3. For any future approved archive relocation, first record original and destination SHA and retain a verified copy. If relocation needs rollback, restore to a separate location, compare hashes and path dependencies, then request promotion approval.
4. Review Git and process status and recheck the 52 protected fingerprints before resuming. Preserve uncommitted changes and untracked source. No reset, clean, destructive Git action or automatic deletion is part of rollback.
