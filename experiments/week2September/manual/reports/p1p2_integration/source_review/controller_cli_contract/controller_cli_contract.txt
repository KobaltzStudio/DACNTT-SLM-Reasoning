=== HELP: scripts\run_experiment.py ===
usage: run_experiment.py [-h] --method
                         {B0,B2,B3,B4,B5,ablation_shuffled_scores} --seed SEED

                         [--pilot-budget PILOT_BUDGET]
                         [--pilot-eval-limit PILOT_EVAL_LIMIT] [--model MODEL]
                         [--revision REVISION] [--dtype {auto,bf16,fp32,fp16}]

Run one method and one training seed through the Task 7 schedule (analysis_plan.md section 3).

  S_0 (shared by all runs): eval D_dev, eval D_test, NLL of the pool
  t = 0..M-1: select B_t -> train S_t + B_t -> S_{t+1} -> eval D_dev, eval D_test -> NLL when needed

NLL per method: B4, B5 and the ablation at S_1 and S_2 (selection and/or T7-6, T7-7); B2 too when
--b2-nll is given (sensitivity analysis of T7-7); B0 and B3 never beyond S_0. S_3 is never scored.

Each step is one subprocess, so GPU memory is released between steps. A finished step leaves a marker in
<run-dir>/.done/ with its command and duration; re-running the same command skips finished steps and redoes
the interrupted one (eval_student.py also resumes inside a step). Durations are appended to
<runs-dir>/timing.jsonl, which is what the cost estimate of the main run comes from.

B4 and B5 select the same B_0 at S_0, so with the same seed S_1 is shared (task7_decisions.md): when the
other method's round 0 is finished and its trajectory list is identical, its adapter, evaluations and NLL
are copied, and the marker records the source.

Layout:
  <runs-dir>/S0/{eval_dev,eval_test,nll}.jsonl
  <runs-dir>/<method>_seed<seed>/round_NNN/{train_set.json,selection_log.jsonl}
  <runs-dir>/<method>_seed<seed>/S<t>/{adapter/,eval_dev.jsonl,eval_test.jsonl,nll.jsonl}
  <runs-dir>/<method>_seed<seed>/checkpoint_log.jsonl

--pilot is for testing the pipeline only: --pilot-problems builds a small pool from the first problems of the
official pool, with a smaller budget and evaluation limit. Keep --runs-dir apart from the main runs.

Usage (from experiments/week2September/manual/):
  python scripts/run_experiment.py --method B5 --seed 13 --runs-dir runs/main
  python scripts/run_experiment.py --method B5 --seed 13 --runs-dir runs/main --dry-run

options:
  -h, --help            show this help message and exit
  --method {B0,B2,B3,B4,B5,ablation_shuffled_scores}
  --seed SEED
  --runs-dir RUNS_DIR
  --backend {hf,vllm}   evaluation backend
  --eval-batch EVAL_BATCH

                       [--limit LIMIT] [--model MODEL] [--revision REVISION]
                       [--dtype {auto,bf16,fp32,fp16}]

Evaluate a Student checkpoint on D_dev or D_test with the frozen evaluation protocol.

Protocol (config/experiment_config.json "evaluation"): prompt v1, greedy decoding,
max_new_tokens 512, answers scored by answer_utils.evaluate_output
(invalid_format counts as incorrect; format compliance reported separately).

Greedy is enforced explicitly: the Qwen generation_config ships sampling defaults and
repetition_penalty 1.05, which would otherwise still apply under do_sample=False.

Also records lenient_correct (last number anywhere in the output, format ignored): the registered
secondary metric of T7-5, always reported with strict accuracy and format compliance. Accuracy per
capability is added on D_dev, over the problems with manual labels.

Backends:
  hf    transformers generate (default; used by the Task 5 smoke test)
  vllm  vLLM with the same greedy settings; needs a bf16 GPU (L4/A100). A LoRA adapter is merged into a
        temporary model directory first, exactly as the hf backend merges it before generating.

Output (resumable: problem_ids already in --out are skipped):
  --out           one JSON line per problem
  --summary       accuracy, format compliance, output length, timing, memory

=== HELP: scripts\compute_nll.py ===
usage: compute_nll.py [-h] --tag TAG [--adapter ADAPTER] --out OUT
                      [--batch-size BATCH_SIZE] [--limit LIMIT] [--pool POOL]
                      [--model MODEL] [--revision REVISION]
                      [--dtype {auto,bf16,fp32,fp16}]

Score every verified pool trajectory under a Student checkpoint (one forward pass, no backward).

Per trajectory tau (trajectory tokens only, the end-of-turn token excluded):
  nll_sum    = sum_t -log p(tau_t | x, tau_<t)
  ell        = nll_sum / n_tokens            (length-normalized NLL; input of L_proxy, config "learnability")
  brier_sum  = sum_t || pi_t - onehot(tau_t) ||^2
               (Brier residual; stored so the LARK score, arXiv 2605.30651 Eq. 7, can be computed
                later without another pass. Exploratory, not part of the frozen L_proxy.)

L_proxy itself is not computed here: it needs ell over the whole pool (median / IQR rule) and
is derived in the analysis step.

--pool defaults to the official pool v1 (trajectory/pool/pool_v1_verified.jsonl). The Task 5 smoke test
scored the preliminary pool; reproduce it with --pool trajectory/pool/batch_100_teacher_verified.jsonl.

Usage (from experiments/week2September/manual/):
  python scripts/compute_nll.py --tag S0 --out reports/task5/smoke_test/nll_pool_S0.jsonl       --pool trajectory/pool/batch_100_teacher_verified.jsonl
  python scripts/compute_nll.py --tag S1_seed13 --adapter <adapter_dir>       --out reports/task5/smoke_test/nll_pool_S1_seed13.jsonl --pool trajectory/pool/batch_100_teacher_verified.jsonl

options:
  -h, --help            show this help message and exit
  --tag TAG
  --adapter ADAPTER
  --out OUT
  --batch-size BATCH_SIZE
  --limit LIMIT
  --pool POOL           verified pool to score (default: pool v1)
  --model MODEL         override the Student model (pipeline tests only;
                        default: config student.model)
  --revision REVISION   revision for --model
